The chain is `202611160001_phase1`, `202611170001_server_table_security`, `202611170002_operations_finance`, `202611170003_history_guards`. No DB connection, current catalog introspection, migration-status query or migration execution was made in this audit. The live checksum, policies, grants, pending/failed history and drift remain unverified.

| Area | Finding and next check |
| --- | --- |
| SQL-only foreign keys | Operations/finance SQL defines `work_branch_fk`, `work_client_fk`, `work_unit_fk`, `work_executive_fk`; Prisma models only the four scalar UUIDs. SQL uses delete restriction and default update behavior. Model both relation ends and map names and referential actions explicitly in a later additive reconciliation. Independent FKs do not enforce a coherent branch/client/unit tuple. |
| SQL-only checks and permissions | Phase 1 has scope exactly-one and six positive versions; operations SQL has movement positivity and different buckets, rate positivity/window/scope, invoice totals/window, positive payment/allocation/credit/expense amounts, positive work version; history SQL has unit and bucket checks, invoice state/issue metadata, reversal reason pairing and expense states. SQL also governs RLS, browser privilege revocation, and immutable audit, movements, rates, credit, payment allocations, issued invoice/source, and receipt records. Prisma does not describe these objects. Preserve and test them independently. |
| Missing integrity constraints | Verify branch/client/unit consistency, duplicate scope rows, work queue/status projection consistency, status transition validity, rate overlap at identical pricing dimensions and valid business-policy version. Existing application checks are useful but need concurrency verification. SQL invoice guard does not provide full cross-row allocation/client/currency checks. |
| Missing foreign keys | Neither Prisma relations nor SQL FKs bind RateContract to client/branch/garment/service, Invoice to client/branch, or Payment to client. Audit/movement/attachment/idempotency actor UUIDs are scalar; choose historical deletion and system-actor policy before enforcing. Movement line/reference and delivery assignees embedded in JSON cannot have ordinary FK enforcement. |
| Missing financial relationships | BillingAllocation already uniquely joins a whole order to an invoice. PaymentAllocation already references payment and invoice; CreditNote references invoice. Missing relational cycle, stable issued line/source/rate associations beyond JSON snapshot and whole-order allocation, scope/currency consistency, and expense branch/unit/approval actor/vendor references. Model these only to the extent required by approved accounting rules. |
| Candidate missing indexes | BillingAllocation.invoiceId, PaymentAllocation.paymentId and CreditNote.invoiceId lack supporting non-PK indexes in the chain. Consider WorkOrder client/unit/completion and delivery-assignment projections; effective-rate dimensions including scope and currency; invoice branch/issued-date, expense filters and lease-ready outbox indexes. Confirm write cost and realistic query plans before adding. |
| Unsafe JSON assumptions | `server/work.ts`, `lib/work-queues.ts`, `server/finance.ts`, and `server/reports.ts` each cast persisted WorkState; `server/jobs.ts` casts invoice snapshots and performs topic parsing; business policy, outbox payload and replay responses are also JSON. Add versioned runtime decoders, bounded element/field validation, legacy fixtures, and safe degraded read/failure messages. Never silently drop malformed amounts or quantities. Keep source/snapshot immutability and test forward compatibility. |
| Evolution | CRM leads, pickups, stop grouping, notifications and managed resource records need explicit relational ownership. Preserve aggregate writes and use measured projections or bounded extraction where cross-order queries need them. A normalized hash confirms source identity only. Full staging catalog comparison must inspect defaults, FK actions, functions, policies, checks, grants and indexes. |

Existing tests cover disabled actors, role/scope changes, assignment and private endpoints. Reassess every new route and replay across non-matching payloads, key reuse, transfer, revoked role/scope and stale sessions. ## Finance, notifications and reliability

- Pricing already snapshots rate/date/source, performs exact minor-unit arithmetic, and blocks unresolved rates. Establish client rate effective date, allowed fallback, tax, rounding, legal identity/layout, credits/refunds, numbering, currency and financial review. Add a rate-overlap concurrency test, approved pricing golden cases, credit/refund acceptance, and reconciliation across ledger, billing, receipts, credits and reports. Expenses have lifecycle status and need approved scope, evidence and review rules. Reporting has limits and balances are current, so historical as-of statements, opening balances and full expense/statement drilldowns are gaps.
- `server/jobs.ts` and `scripts/worker.ts` implement leases, bounded retry and handlers for invoice PDFs, report exports, scheduled draft creation and gated staff invites. `master.changed` and `work.changed` are acknowledged internal events, with no user delivery. Design idempotent in-app records for assignment, inbound receipt, discrepancies, final release, same-route grouping, proofs, billing ready, and overdue items. Add unread/read state, safe redirect, retry visibility, stale-assignment suppression and timestamps. External notifications require provider approval and recipient preferences. Inbound WhatsApp should deduplicate provider events and produce a reviewable lead only.
- PostgreSQL stores evidence/PDF bytes and outbox stores export bytes temporarily. Evaluate private object storage with authorization on every access, quarantined uploads, content validation/scanning, retention, resumability and size controls. Keep old records accessible under equivalent controls. Establish worker heartbeat, lag, dead-letter handling, retry/runbook, timeouts, DB pool sizing and backup/restore. Verify webhook privacy and retention if enabled.
- `components/QueueRefresh.tsx` refreshes visible queues every 20 seconds. Measure sustained polling/database load, assignment and queue searches, JSON scans, role KPI queries, worker claim ordering and long history/report caps. Existing work detail limits include 100 audit rows and 500 quantity movements. Tune indexes, narrow projections, cursor/pagination and backoff before adding real-time infrastructure.
